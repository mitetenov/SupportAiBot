# Telegram HTML Message Formatting Design

## Overview
Currently, LLM responses and FAQ instructions contain standard Markdown syntax (such as `**bold**`, `*italic*`, `` `code` ``, `[links](url)`). Because the bot sends messages to Telegram with plain text mode (`parse_mode=None`), raw asterisks and markdown symbols are displayed literally to users.

This design introduces a robust Markdown-to-Telegram-HTML conversion pipeline with an automatic plain-text fallback on Telegram parse errors, ensuring clean formatting and 100% message delivery reliability.

## Goals & Requirements
1. Convert Markdown formatting generated by LLMs or FAQ templates into Telegram-compatible HTML tags (`<b>`, `<i>`, `<code>`, `<pre>`, `<s>`, `<a href="...">`, `<blockquote>`).
2. Safely escape HTML characters (`&`, `<`, `>`) so arbitrary text cannot cause HTML injection or malformed entity errors.
3. Handle chunking without breaking HTML tags across message boundaries.
4. Provide graceful fallback in `TelegramMessageSender`: if Telegram rejects the formatted HTML (e.g. malformed markup), immediately retry and send as plain text without crashing or dropping the message.
5. Maintain high test coverage (>=85%) with full test coverage for the formatter and sender changes.

## Architecture & Components

### 1. Markdown to Telegram HTML Converter (`app/bot/formatting.py`)
A dedicated module that implements `markdown_to_telegram_html(text: str) -> str`:
- **Step 1: Code protection:** Extract multi-line code blocks (```` ```...``` ````) and inline code (`` `...` ``), replacing them with unique placeholders so their internal markdown/HTML characters are preserved literally.
- **Step 2: HTML escaping:** Escape `<` -> `&lt;`, `>` -> `&gt;`, `&` -> `&amp;` in the non-code text.
- **Step 3: Block formatting:** Convert blockquotes (`> text`) into `<blockquote>...</blockquote>`.
- **Step 4: Inline formatting:**
  - `**bold**` and `__bold__` -> `<b>...</b>`
  - `*italic*` and `_italic_` (with word boundary / delimiter safety) -> `<i>...</i>`
  - `~~strike~~` -> `<s>...</s>`
  - Markdown links `[text](url)` -> `<a href="url">text</a>` (validating that the URL is a valid web or tg URL).
- **Step 5: Code restoration:** Restore code blocks as `<pre><code>...</code></pre>` and inline code as `<code>...</code>` with their contents HTML-escaped.

### 2. Telegram Message Sender (`app/bot/sender.py`)
Enhance `TelegramMessageSender._send_chunks`:
- Split messages into chunks based on line breaks before applying HTML conversion.
- For each chunk, format with `markdown_to_telegram_html(chunk)`.
- Attempt sending with `parse_mode="HTML"`.
- If an exception occurs during sending (specifically Telegram parse error / `TelegramBadRequest` or syntax failure), log a warning and fallback to sending the original unformatted chunk with `parse_mode=None`.

### 3. Verification & Testing
- Unit tests in `tests/test_formatting.py`:
  - Code blocks, multiline code, language hints.
  - Bold, italic, strikethrough, links, blockquotes, and lists.
  - Protection against HTML injection (`<script>`, `foo < bar & baz > qux`).
  - Complex nesting and edge cases (unclosed tags, underscores in URLs / identifiers).
- Unit tests in `tests/test_sender.py`:
  - Verify `send_message` is called with `parse_mode="HTML"`.
  - Verify fallback behavior when `send_message` fails due to formatting error.
